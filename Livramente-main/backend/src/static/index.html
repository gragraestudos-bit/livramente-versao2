Livramente

Documentação da API RESTful

Sua biblioteca, suas leituras, suas histórias.

Ana Fargoni, Grazielly Tonelli e Sophia Silva

Visão geral

O Livramente é uma aplicação de biblioteca com funcionalidades de organização de leituras. Esta documentação apresenta todas as rotas da API, organizadas por módulo.

Endereço base

Durante o desenvolvimento local:

http://localhost:3000

Banco de Dados

Para visualizar o Banco de Dados:

http://localhost:8081

Formato dos dados

As requisições com corpo utilizam:

Content-Type: application/json

Autenticação

Rotas protegidas exigem o token do login:

Authorization: Bearer <token>

Autenticação

O login devolve um token JWT (válido por 2 horas). Nas rotas que exigem token, envie o cabeçalho Authorization: Bearer <token>. Sem token ou com token expirado a resposta é 401; rotas de administrador respondem 403 para usuários comuns. Nos dados iniciais, Ana Fargoni (ID 1) é a administradora.

POST/autenticacao/login

Fazer login

Confere e-mail e senha e devolve o token e os dados do usuário.

Acesso

Pública

Corpo da requisição

  • email: e-mail cadastrado.
  • senha: senha do usuário.

Restrições

  • email e senha: textos obrigatórios e não vazios (senão 400).
  • O e-mail é comparado sem espaços nas pontas e em minúsculas.
  • E-mail inexistente e senha errada dão a mesma resposta 401, para não revelar quais e-mails existem.
  • O token expira em 2 horas e a resposta nunca traz a senha.

Exemplo

{
  "email": "ana.fargoni@gmail.com",
  "senha": "<senha cadastrada>"
}

Respostas

  • 200 Login realizado, com token e usuario.
  • 400 E-mail ou senha não informados.
  • 401 E-mail ou senha inválidos.

Exclusão lógica (soft delete)

Nenhum registro das entidades principais é apagado fisicamente. Ao excluir, o sistema apenas marca a coluna booleana removido = TRUE, e todas as consultas (GET, validações e verificações de unicidade) passam a ignorar os registros removidos. Isso preserva o histórico e a integridade referencial.

Entidades com removido

  • usuario, livro, emprestimo
  • resenha, comentario, curtida
  • favorito, estante
  • A tabela arquivo é a exceção: continua sendo removida fisicamente quando fica órfã.

Comportamento

  • As rotas DELETE marcam removido = TRUE em vez de apagar.
  • Índices únicos (e-mail, ISBN, resenha por livro) passam a valer apenas entre os registros ativos, permitindo reaproveitar valores de itens removidos.
  • Em curtida, favorito e estante, adicionar de novo um item antes removido o reativa automaticamente.
Mudanças de endpoints nesta entrega
  • POST /arquivos passou a ser público, para permitir o cadastro de usuário com foto de perfil sem exigir login prévio.
  • DELETE /arquivos/orfaos (apenas administradores): remove imagens sem referência (faxina de arquivos órfãos).
  • GET /resenha/livro/:id: lista as resenhas ativas de um livro específico.

POST/usuario

Cadastrar usuário

Cria uma conta de usuário comum.

Acesso

Pública

Corpo da requisição

  • nome: nome do usuário.
  • email: e-mail válido e único.
  • senha: de 6 a 72 caracteres.
  • foto_perfil (opcional): texto com caminho da foto.
  • id_foto_perfil (opcional): ID de um arquivo enviado em /arquivos.

Restrições

  • Rota aberta, sem token.
  • nome: obrigatório, não vazio nem só espaços, até 100 caracteres.
  • email: obrigatório, formato válido (algo@dominio.ext, sem espaços), até 150 caracteres; é salvo em minúsculas e não pode já estar cadastrado (409).
  • No banco, o e-mail aceita só letras, números e os símbolos . _ % + - antes do @, e domínio com extensão de 2 ou mais letras.
  • senha: texto de 6 a 72 caracteres (limite do bcrypt, medido em bytes); é salva apenas como hash.
  • foto_perfil: até 255 caracteres; vazio ou null significa sem foto.
  • id_foto_perfil: inteiro maior que zero de um arquivo já enviado em /arquivos; arquivo inexistente gera 400.
  • O usuário criado é sempre comum: o cliente não define administrador.

Exemplo

{
  "nome": "Maria Souza",
  "email": "maria@email.com",
  "senha": "123456"
}

Respostas

  • 201 Usuário criado.
  • 400 Dado inválido (nome, e-mail, senha ou foto).
  • 409 E-mail já cadastrado.
PUT/usuario/:id

Editar usuário

Altera nome, e-mail e foto. Cada usuário edita somente a si mesmo; as fotos não enviadas são mantidas.

Acesso

Requer token

Parâmetros da URL

  • id: ID do usuário.

Corpo da requisição

  • nome: novo nome.
  • email: novo e-mail.
  • foto_perfil (opcional): texto ou null.
  • id_foto_perfil (opcional): ID do arquivo ou null para remover.

Restrições

  • O ID deve ser um número inteiro maior que zero.
  • Exige token válido e não expirado; o usuário do token precisa existir (senão 401).
  • Só é possível editar o próprio usuário (senão 403).
  • O usuário deve existir (senão 404).
  • nome e email: obrigatórios, com as mesmas regras do cadastro; o e-mail não pode pertencer a outro usuário (409).
  • foto_perfil e id_foto_perfil: se omitidos, mantêm o valor atual; null ou vazio remove; valor inválido gera 400.
  • Não altera senha nem administrador.

Respostas

  • 200 Usuário atualizado.
  • 400 Dado inválido.
  • 403 O ID não é o seu.
  • 404 Usuário não encontrado.
  • 409 E-mail já usado por outro usuário.

POST/livro

Cadastrar livro

Cria o livro com todos os exemplares disponíveis.

Acesso

Somente administrador

Corpo da requisição

  • titulo: título.
  • autor: autor.
  • genero: gênero.
  • quantidade_exemplares: inteiro maior que zero.
  • sinopse, capa, editora (opcional): textos.
  • isbn (opcional): exatamente 13 dígitos.
  • ano_publicacao, numero_paginas (opcional): inteiros maiores que zero.

Restrições

  • Exige token válido e não expirado; o usuário do token precisa existir (senão 401).
  • Exige usuário administrador (senão 403).
  • titulo (até 200), autor (até 150) e genero (até 80 caracteres): obrigatórios, não vazios nem só espaços.
  • sinopse, capa (até 255) e editora (até 150): opcionais; precisam ser texto, e vazio vira null.
  • isbn: opcional; exatamente 13 dígitos numéricos e único entre os livros (409).
  • ano_publicacao e numero_paginas: opcionais; inteiros maiores que zero.
  • quantidade_exemplares: obrigatório, inteiro maior que zero.
  • exemplares_disponiveis começa igual à quantidade total; data_cadastro é automática.

Respostas

  • 201 Livro cadastrado.
  • 400 Dado inválido.
  • 403 Não é administrador.
  • 409 ISBN já cadastrado.
PUT/livro/:id

Editar livro

Substitui os dados do livro (mesmos campos do cadastro). Ao mudar a quantidade, os disponíveis são recalculados.

Acesso

Somente administrador

Parâmetros da URL

  • id: ID do livro.

Corpo da requisição

  • titulo, autor, genero e quantidade_exemplares: obrigatórios, como no cadastro.

Restrições

  • O ID deve ser um número inteiro maior que zero.
  • Exige token válido e não expirado; o usuário do token precisa existir (senão 401).
  • Exige usuário administrador (senão 403).
  • O livro deve existir (404).
  • Substitui o cadastro inteiro: os campos seguem as regras do cadastro, e um campo opcional omitido é apagado (vira null).
  • A diferença entre a nova e a antiga quantidade é somada aos disponíveis; se o resultado ficar negativo, a edição é recusada (409).
  • O isbn não pode pertencer a outro livro (409).

Respostas

  • 200 Livro atualizado.
  • 400 Dado inválido.
  • 404 Livro não encontrado.
  • 409 Quantidade menor que o total emprestado, ou ISBN repetido.

POST/emprestimo

Solicitar empréstimo

Cria uma solicitação pendente em nome do usuário logado.

Acesso

Requer token

Corpo da requisição

  • id_livro: ID do livro.

Restrições

  • Exige token válido e não expirado; o usuário do token precisa existir (senão 401).
  • id_livro: inteiro maior que zero; o livro deve existir (404).

}

Respostas

  • 400 ID inválido.
  • 404 Livro não encontrado.
  • 409 Já existe solicitação pendente ou empréstimo ativo deste livro.
PUT/emprestimo/:id

Alterar status

Cancelar: só o dono e só se estiver pendente. Aprovar e recusar: administrador, só se pendente. Devolver: administrador, só se aprovado.

Acesso

Requer token

Parâmetros da URL

  • id: ID do empréstimo.

Corpo da requisição

  • status: aprovado, recusado, cancelado ou devolvido.
  • data_prevista_devolucao (opcional): AAAA-MM-DD, obrigatória ao aprovar e não pode ser anterior a hoje.

Restrições

  • O ID deve ser um número inteiro maior que zero.
  • Exige token válido e não expirado; o usuário do token precisa existir (senão 401).
  • status: um de aprovado, recusado, cancelado ou devolvido; outro valor gera 400.
  • O empréstimo deve existir (404).
  • cancelado: só o dono do empréstimo e só se estiver pendente (senão 403).
  • aprovado, recusado e devolvido: só administrador (senão 403).
  • aprovado: só se estiver pendente (409); exige data_prevista_devolucao em AAAA-MM-DD, data real do calendário e não anterior a hoje (400); precisa haver exemplar disponível (409). Registra data_emprestimo como hoje e reduz um exemplar disponível.
  • recusado: só se estiver pendente (409).
  • devolvido: só se estiver aprovado (409). Registra data_devolucao como hoje e devolve um exemplar ao acervo.
  • A operação é feita em transação: se algo falhar, nada é alterado.

Exemplo

{
  "status": "aprovado",
  "data_prevista_devolucao": "2026-12-01"
}

Respostas

  • 200 Status atualizado.
  • 400 Status ou data inválidos.
  • 403 Sem permissão.
  • 404 Empréstimo não encontrado.
  • 409 Status atual não permite a mudança, ou sem exemplares.

Permite associar livros aos usuários, consultar suas leituras, alterar categorias e remover livros da estante. As categorias disponíveis são quero_ler, lendo e ja_li. Todas as rotas exigem token, e o :id_usuario deve ser o do usuário logado (caso contrário, 403).

GET/estante/:id_usuario

Consultar estante de um usuário

Retorna os livros de um usuário, organizados pelas três categorias de leitura.

Parâmetros da URL

  • id_usuario: ID do usuário cuja estante será consultada.

Restrições

POST/estante

Adicionar livro à estante

Cria uma associação entre um usuário e um livro, definindo a categoria da leitura.

Parâmetros obrigatórios no corpo

  • id_livro: identificador do livro.
  • categoria: categoria de leitura.

Restrições

  • O ID do livro deve ser um número inteiro maior que zero. O usuário é o dono do token.
  • O usuário e o livro devem existir.
  • A categoria deve ser quero_ler, lendo ou ja_li.
  • O mesmo livro não pode ser adicionado duas vezes à estante do mesmo usuário.
  • Exige token; a estante é sempre a do usuário logado.
  • id_livro e categoria são obrigatórios no corpo; a categoria diferencia maiúsculas de minúsculas.

{
  "id_livro": 4,
  "categoria": "quero_ler"
}

}

Arquivos (imagens)

Upload de fotos de perfil e capas. O arquivo é guardado no banco; use o id_arquivo retornado em id_foto_perfil do usuário.

POST/arquivos

Enviar imagem

Envio multipart/form-data, com a imagem no campo arquivo. Aceita JPEG, PNG, WEBP e GIF de até 5 MB (o conteúdo real é verificado).

Acesso

Requer token

Corpo da requisição

  • arquivo: arquivo de imagem.

Restrições

  • Exige token válido e não expirado; o usuário do token precisa existir (senão 401).
  • Enviar como multipart/form-data, com um único arquivo no campo chamado arquivo (outro campo ou mais de um arquivo gera 400).
  • Tamanho máximo de 5 MB (413).
  • Tipos aceitos: image/jpeg, image/png, image/webp e image/gif.
  • O tipo informado precisa coincidir com o conteúdo real do arquivo; arquivos disfarçados, SVG, HTML etc. recebem 415.
  • O nome original é guardado com até 255 caracteres.
  • Não existe rota para excluir arquivos.

Respostas

  • 201 Arquivo salvo, com id_arquivo.
  • 400 Nenhum arquivo ou campo errado.
  • 413 Maior que 5 MB.
  • 415 Tipo não permitido.
